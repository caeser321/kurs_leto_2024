# Android-приложение «Анкета клиента»

APK, который заказчик ставит на планшет. Клиент заполняет анкету,
расписывается стилусом — приложение само собирает PDF и сохраняет его
в памяти планшета. **Сервер и интернет не нужны.**

## Как получить APK

### Через GitHub (ничего ставить не надо)

В репозитории есть workflow [`.github/workflows/android-apk.yml`](../../.github/workflows/android-apk.yml).

1. Вкладка **Actions** → **Сборка APK** → **Run workflow**.
2. Дождаться зелёной галочки (5–10 минут).
3. Внизу страницы запуска скачать артефакт **anketa-apk**.

Внутри — `app-debug.apk`, его и передаёте заказчику.

### Локально

Нужны Android Studio (или Android SDK) и JDK 21.

```bash
cd client-forms && npm install
cd app && npm install
npm run apk
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

Отдельные шаги, если нужно вмешаться в процесс:

```bash
npm run build   # собрать веб-часть в www/
npm run sync    # www/ -> Android-проект
npm run open    # открыть проект в Android Studio
```

## Установка на планшет

APK не из Google Play, поэтому Android попросит разрешение:

1. Скопировать файл на планшет (кабель, почта, мессенджер).
2. Открыть его в файловом менеджере.
3. Разрешить установку из этого источника, когда система спросит.

Debug-сборка подписана отладочным ключом — для проверки и внутреннего
использования этого достаточно. Для публикации в Google Play или
для «нормальной» подписи нужен свой keystore (см. ниже).

## Где хранятся анкеты

В приватной памяти приложения (`Directory.Data` → внутреннее хранилище):

```
anketa/2026/08/20260816-143022-K3F9QA__ivanov-petr-sergeevich.pdf
anketa/2026/08/20260816-143022-K3F9QA__ivanov-petr-sergeevich.json
```

Так выбрано намеренно:

- **не нужны разрешения** — приложение не просит доступ к памяти устройства;
- **персональные данные закрыты** — другие приложения и файловые менеджеры
  туда не заглядывают;
- при удалении приложения данные удаляются вместе с ним — поэтому анкеты
  надо регулярно выгружать.

Рядом с каждым PDF лежит JSON с теми же данными: если позже понадобится
свести анкеты в таблицу или загрузить в CRM, разбирать PDF не придётся.

Базы данных нет: экран «Архив» строится обходом каталога. Для сотен и
даже тысяч анкет на планшете этого достаточно.

### Как забрать файлы с планшета

- **Одну анкету** — кнопка «Отправить PDF» сразу после сохранения
  или «Поделиться» в архиве.
- **Все сразу** — в архиве кнопка «Выгрузить все».

Дальше открывается системное меню Android: почта, мессенджер,
облачный диск, подключённая флешка — куда удобнее.

## Подпись стилусом

Работает на Pointer Events. WebView в Android построен на Chromium,
поэтому активные стилусы (S Pen и аналоги) сообщают `pointerType: 'pen'`
и силу нажатия — нажим задаёт толщину линии. Пока в поле пишут пером,
касания пальцем игнорируются, чтобы лежащая на экране ладонь
не оставляла следов.

Проверьте на конкретной модели планшета: у простых ёмкостных стилусов
(без активного пера) нажима нет, и толщина считается по скорости движения.

## Устройство

```
capacitor.config.json   идентификатор приложения и название
build.mjs               сборка www/: esbuild + копирование шрифтов и стилей
serve.mjs               локальный просмотр www/ в браузере
src/main.js             экран анкеты: проверка, сборка PDF, сохранение
src/archive.js          экран архива и выгрузка файлов
src/device-store.js     хранилище: файлы на устройстве / IndexedDB в браузере
src/fonts.js            загрузка шрифтов с кириллицей для PDF
html/                   разметка экранов
android/                Android-проект (создан `cap add android`)
```

Логика анкеты не дублируется: описание полей, проверки, генерация PDF
и поле для подписи берутся из общих модулей родительского каталога
(`../src`, `../public/js`, `../forms/anketa.json`). Поэтому изменение
анкеты в `forms/anketa.json` меняет и веб-версию, и приложение.

### Проверка без планшета

```bash
npm run serve
```

Откроется `http://localhost:4173` — то же приложение в обычном браузере.
Вместо файлов планшета используется IndexedDB, вместо «Поделиться» —
скачивание файла. Удобно, чтобы посмотреть вёрстку и проверить PDF.

## Настройка

**Название и идентификатор** — `capacitor.config.json`:

```json
{ "appId": "ru.anketa.client", "appName": "Анкета клиента" }
```

`appId` менять до первой установки: Android считает его именем пакета,
и приложение с другим `appId` встанет рядом как отдельное. После правки:

```bash
npx cap sync android
```

**Состав анкеты** — `../forms/anketa.json`, затем `npm run build`.

**Иконка** — файлы `android/app/src/main/res/mipmap-*/`. Проще всего
заменить через Android Studio: *File → New → Image Asset*.

### Релизная подпись

Для сборки, которую не стыдно раздавать вне тестов:

```bash
keytool -genkey -v -keystore anketa.keystore -alias anketa \
        -keyalg RSA -keysize 2048 -validity 10000
```

Дальше прописать keystore в `android/app/build.gradle` (блок
`signingConfigs`) и собирать `./gradlew assembleRelease`.
Keystore в репозиторий не класть — потеря файла означает,
что обновить установленное приложение уже не получится.

## Персональные данные

Анкета собирает паспортные данные. Они лежат только на планшете
и в тех местах, куда их выгрузит заказчик. При выборе внешнего
хранилища стоит помнить про 152-ФЗ: персональные данные граждан РФ
должны храниться в базах на территории России, поэтому Google Drive
и подобные сервисы для такой выгрузки не годятся.

Планшет с анкетами разумно защитить паролем или отпечатком
и включить шифрование устройства.
